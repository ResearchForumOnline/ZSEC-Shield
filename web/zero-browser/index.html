Blocking is not the same as total protection

Removing configured ads and trackers can reduce exposure and distraction. It cannot guarantee that every site, extension, download or account is safe. Browser and operating-system updates still matter.

Privacy contract

Browsing is not a telemetry product.

The local preview has no analytics endpoint, advertising identifier, account requirement or remote-control channel. Its privacy promise is specific and testable—not a vague “private mode” badge.

The preview does not collect

  • Browsing history or visited page content.
  • Form entries, cookies or search queries.
  • Private-browsing history or diagnostics.
  • Affiliate-attribution replacements.
  • Automatic page screenshots or memory contents.

Future network requests stay bounded

  • Update checks disclose only documented release fields.
  • Diagnostics remain a separate opt-in.
  • URLs, query strings and user identifiers are scrubbed.
  • Sync must be independently encrypted before release.
  • Any policy change requires clear release notes.

Browser security architecture

A browser fork is an update operation, not a paint job.

A future Zero Browser distribution must preserve Chromium’s process separation, renderer sandbox and Site Isolation while keeping its own patch set deliberately small. The extension preview does not claim that operation already exists.

  • Never ship with the Chromium sandbox disabled.
  • Never install a root certificate to inspect traffic.
  • Merge upstream security fixes weekly and on emergency cadence.
  • Use signed update metadata with expiry and rollback protection.
  • Carry complete Chromium and third-party licence notices.

Phased delivery

Earn responsibility one layer at a time.

Controlling a browser means accepting continuous security-maintenance duties. The roadmap does not call a mock-up or an extension a finished browser.

Coverage without theatre

What blocking can—and cannot—do.

A transparent browser should show the user which controls are active, why a site broke and how to make a narrow site exception. It should not hide limitations behind a green shield.

Preview scope

Configured local ad and tracker rules plus best-effort YouTube interface cleanup in compatible Chromium-based browsers.

Design commitment

Clear per-site controls, visible exceptions, permission explanations and no forced search provider or affiliate injection.

Future distribution

A separately maintained Chromium browser with signed builds, a fast updater, complete notices and preserved sandbox boundaries.

Not promised

Every YouTube ad blocked, every malicious site prevented, anonymity, immunity from browser exploits or protection from all hackers.

Optional recovery, later

Passkeys and YubiKeys belong in recovery—not in your way.

A future encrypted-settings or sync design may let a compatible authenticator help recover wrapped keys after physical presence and local verification. Ordinary browsing should not require repeated security-key touches.

Questions, answered plainly

Zero Browser FAQ

Is Zero Browser already a standalone browser?

No. The current product is a Manifest V3 privacy and security extension preview. A separately branded Chromium distribution is a future phase that requires continuous upstream security merges, signed builds, complete licence notices and a tested updater.

Does Zero Browser block every YouTube ad?

No. The preview applies local declarative blocking rules and best-effort interface cleanup, but YouTube and other sites change frequently. Zero Browser does not promise perfect ad blocking or uninterrupted coverage on every site.

Does Zero Browser collect browsing history?

The local preview does not collect or upload browser history, page content, form data, cookies or search queries. Future update checks may disclose only documented product and rollout information, and crash diagnostics must remain a separate opt-in.

Does Zero Browser install a root certificate or inspect encrypted traffic?

No. The extension preview does not proxy traffic, install a local root certificate or break TLS. A future Chromium distribution must retain the browser sandbox and Site Isolation and must not depend on TLS interception.

Will Zero Browser support YubiKeys and passkeys?

Optional passkey or YubiKey-backed recovery is part of the future design for encrypted settings or sync. It is not shipped in the extension preview and would not be required for ordinary browsing.

How will Zero Browser stay secure as Chromium changes?

A future browser distribution needs a deliberately small patch set, automated upstream monitoring, weekly and emergency security merges, signed update metadata, staged release rings and tested rollback. Until that operation exists, the project is not described as a maintained Chromium browser binary.
