Automatic file monitoring you can verify.

Zero Security 0.2 can watch selected folders using native operating-system file events, scan changed files locally, verify signed data-only rules and place configured matches into authenticated encrypted quarantine when you explicitly enable it.

Install safely

Verify, extract, inspect, then run.

Use a test folder first. Your operating system may warn because these developer archives are unsigned; do not bypass a warning you do not understand.

Verify SHA-256

Windows: Get-FileHash .\zsec-shield-*.zip -Algorithm SHA256. macOS: shasum -a 256 zsec-shield-*.tar.gz. Linux: sha256sum zsec-shield-*.tar.gz.

Extract the archive

Keep the extracted folder together. The executable, libraries, manifest, licences and threat-model documents form one reviewed bundle.

Inspect status

Run zsec-shield status --json, then zsec-shield replacement-readiness --json. Replacement readiness must remain blocked in this preview.

Start with a test folder

Use the foreground command below against a non-critical directory. Quarantine stays off unless you add --quarantine.

Automatic post-change protection

One explicit command starts the monitor.

The native observer starts before the baseline scan. Changed paths are debounced, scanned serially and backed by periodic reconciliation.

>

Windows example

.\zsec-shield.exe protect "$env:USERPROFILE\Downloads" --backend native

$

macOS or Linux example

./zsec-shield protect "$HOME/Downloads" --backend native

Use --json-lines for ordered session events, --report PATH for an atomic final report, or --backend auto to permit a clearly disclosed polling fallback. Press Ctrl+C for an orderly stop.

Know what this release is

Useful companion protection, not replacement antivirus.

Zero Security 0.2 performs local exact-rule scanning after filesystem activity and can encrypt configured matches for recovery. It does not yet mediate file access, inspect process memory or behaviour, filter network traffic, register with Windows Security, run as a protected service, or provide independently certified detection efficacy.

That boundary is enforced in code: replacement-readiness returns a non-success decision with keep_existing_protection, and there is no override.
